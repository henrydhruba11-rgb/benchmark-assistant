# Benchmark 设计原则（跨源提炼）

每条原则标注来源（源 ID + 小节）。skill 在构建/复盘/梳理时引用这些原则作为依据；playbooks 按编号（原则 1、原则 12…）引用，故编号 1-16 须保持稳定。

> 源 ID 仅使用 5 个规范值：chapter6 / chapter12 / guidebook / chang-survey / yehudai-survey。小节描述与 `references/knowledge-map.md` 的映射保持一致。

### 1. 评估对象解耦：测模型还是测 harness

同一模型在不同 harness 中表现差异悬殊；用模型替换实验（model swap）区分瓶颈在模型还是 harness。

来源:chapter6 §引言（评估的对象不应只是模型）；yehudai-survey §7 Discussion > Decoupling LLM & Harness Evaluation。

为什么：Agent 表现不佳时，改进方向可能是 harness 而非换模型；不区分两者会把工程问题误当成能力问题。

### 2. 明确性 vs 开放性

任务描述要明确到可复现，又不能死板到限制合理解法。GAIA 是范例：目标明确、路径开放。

来源:chapter6 §任务数据集设计的核心挑战（挑战一：明确性与开放性的张力）。

为什么：描述模糊则评估不可复现，描述过死则压制 Agent 的创造性合理解法，两者张力贯穿数据集设计始终。

### 3. 真实性 vs 可控性

真实任务带噪声能显鲁棒性，但威胁可复现。SWE-Bench Verified 用人工筛选在真实与可控间取衡。

来源:chapter6 §任务数据集设计的核心挑战（挑战二：真实性与可控性的平衡）。

为什么：纯合成任务缺乏生态效度，纯真实任务难以稳定复现；分层筛选是平衡两者的工程范式。

### 4. 多样性 vs 系统性

需覆盖典型/边界/陷阱，且系统组织以诊断能力短板。AndroidWorld 标注能力维度+参数化生成。

来源:chapter6 §任务数据集设计的核心挑战（挑战三：多样性与系统性的协调）。

为什么：无系统的多样性只能给出总分，无法定位具体能力短板；能力维度标注是把"杂"变成"可诊断"的关键。

### 5. 成本 vs 覆盖

复杂 agent 任务耗时费 token，规模须在全面与经济间平衡。GAIA 466 题、SWE-Bench Verified 500 题。

来源:chapter6 §任务数据集设计的核心挑战（挑战四：评估成本与覆盖范围）。

为什么：规模并非越大越好；高信噪比的精选子集往往比大而全的低质集更有诊断力，且成本可控。

### 6. 防数据泄漏

公开数据易进训练集，测的是记忆力。手段：答案独特性、附件文件、动态参数生成、时间新鲜度、canary GUID。

来源:chapter6 §任务数据集设计的核心挑战（挑战五：数据泄漏防范）；guidebook §MANAGING CONTAMINATION。

为什么：泄漏会让分数虚高且无法反映泛化能力；canary GUID、参数化生成等手段使泄漏可检测或可规避。

### 7. 可验证性与客观性

验证尽量可执行、客观、可复现：代码可执行、状态检查、关键词搜索；function scorer 优于模糊匹配。

来源:chapter6 §可验证性与客观性保障；guidebook §FUNCTIONAL SCORERS。

为什么：主观/模糊的验证会引入评分噪声，使前后不可复现；可编程验证（数据库状态、文件系统、DOM）才能支撑自动化与回归。

### 8. 难度层次化

分级设计以诊断不同能力短板（GAIA 三级；τ²-bench 业务复杂度分层）。

来源:chapter6 §任务复杂度的层次化设计。

为什么：单一难度的总分无法区分"基础工具不行"还是"长序列思考不行"；层次化设计把改进方向直接读出来。

### 9. Rubric 四准则

基于专家指导 / 全面覆盖（含陷阱）/ 标准权重与一票否决 / 自包含可验证。否决项（如幻觉）与质量正交。

来源:chapter6 §LLM-as-a-Judge：自动化评估的核心（Rubric 四准则）。

为什么：没有 Rubric 的 LLM-as-judge 只是"另一个模型的意见"；四准则让评分可复现、可审计、可防奖励作弊。

### 10. LLM-as-judge 偏见与缓解

已知偏见：长度/位置/自我偏好/格式/输入扰动盲区。缓解：多源异构评判、交换顺序、jury、惩罚冗长、校准。

来源:guidebook §With judge models / §PROS AND CONS OF USING JUDGE-LLMS / §EVALUATING YOUR EVALUATOR；chapter6 §LLM-as-a-Judge：自动化评估的核心（同源模型问题与多源评判）。

为什么：同源 judge 会被钻空子（古德哈特定律）；多源异构评判+定期校准是守住评分有效性的必要手段。

### 11. 轨迹 vs 结果双重覆盖

只看轨迹漏"说了没做到"，只看结果漏"走歪了"。两类评测都应覆盖。

来源:chapter6 §评估指标体系（执行轨迹与最终结果的双重覆盖）。

为什么：轨迹与结果是两件事——Agent 说"订票完成"是轨迹，数据库里真有订单才是结果；任一单看都会留下系统性盲区。

### 12. Pass@k vs Pass^k vs Best@k 不可混用

Pass@k 测能力上限（至少一次成功），Pass^k 测稳定性（全部成功），Best@k 测质量上限。混用导致误判。

来源:chapter6 §评估指标体系（结果与质量指标）。

为什么：回归测试用 Pass@k 会掩盖不稳定性，探索性评估用 Pass^k 会因偶发波动误报；选错指标直接导致错误决策。

### 13. 统计显著性

分差小于噪声带宽时不做切换决策；用配对分析（McNemar）比独立相减灵敏；多重比较要收紧或复跑。

来源:chapter6 §评估结果的统计显著性；guidebook §Statistical validity。

为什么：小样本下的几分差异常落在噪声带宽内；不做配对分析就把抽样噪声当成改进信号，是切换决策最常见的陷阱。

### 14. 可复现性

小差异（prompt/模板/归一化/种子/加载）可致数分偏差；报告须透明，复现极难。

来源:guidebook §So, you can't reproduce reported model scores?。

为什么：不复现的分数无法横向比较，也无法回归；透明报告 prompt、模板、归一化、种子与加载细节是评估可信度的底线。

### 15. 成本非线性增长与优化

多轮上下文累积使成本非线性增长；优化核心是控轮次与上下文（KV Cache 复用、压缩、分层路由）。

来源:chapter6 §Agent 系统的成本分析。

为什么：上下文累积使第 N 轮输入远大于单轮；成本优化的杠杆不在选便宜模型，而在控轮次、稳前缀、压缩历史。

### 16. 评估作为学科 / 持续迭代

评估不是一次性考试，而是嵌入每次决策的持续验证；观察->假设->实验->验证闭环。

来源:chapter6 §从 Benchmark 报告到系统改进（持续迭代：从第一次改进到系统演化）；chang-survey §7 GRAND CHALLENGES AND OPPORTUNITIES FOR FUTURE RESEARCH（Evaluation as a new discipline）。

为什么：模型与任务都在演进，静态评估集会饱和；把评估当成持续学科，才能让每次改进都建立在可检验的证据之上。
